Executive result

No exploitable P0 account-validation issue was identified in the reviewed instruction paths. The current program uses signer-typed authorities, typed Anchor accounts, PDA seed/bump constraints, and request-to-wallet relationships. Recovery state transitions are now covered by native unit tests, and a saturating lamport check in vault withdrawals was replaced with checked post-withdrawal balance calculation.

The B security score is provisional, not an independent audit. The program has not been exercised through an SVM or local validator in this session; account constraints and serialized transaction paths therefore remain unverified. The overall weighted score is 78/100 (B), limited by that testing gap.

Checks that passed in this review

  • Privileged operations use signer-typed accounts; wallet and request PDAs are re-derived with stored bumps and linked with has_one.
  • Guardian policies reject empty, duplicate, owner-colliding, and invalid-threshold configurations.
  • Recovery approval binds to the policy version; duplicate approvals are rejected; execution requires threshold, elapsed timelock, and a non-expired request.
  • Owner cancellation is allowed before the execution delay; expiry is permissionless only after the expiration timestamp.
  • Vault withdrawal math now computes both resulting balances before writing and preserves the rent-exempt reserve.
  • Simulation wrapper refuses unsigned transactions, sets sigVerify: true, never submits, bounds log output, and labels log/CPI observations as heuristics.
  • Prototype UI now distinguishes threshold from execution, uses semantic alert/status announcements, makes the mobile drawer keyboard-dismissible, and provides a real empty notifications state.
